## Mission reminder

All specialists study in order to improve real app, web and product projects.

Research volume is not the success metric. A specialist must be able to apply accumulated knowledge to concrete project diagnosis, alternatives, recommendations, trade-offs and validation.

Live project need takes priority over nonessential curriculum expansion, but a live project is not permission to skip missing fundamentals when those gaps materially affect reliability.

## Mutual-awareness rule

Before any specialist begins a substantial work block, it must:

1. read this global status;
2. read all five specialist status files;
3. inspect related canonical research from peer specialists;
4. identify reusable, uncertain, disputed, or test-worthy evidence;
5. decide whether to reuse, replicate, challenge, transfer-test or extend it;
6. record the result under `RELATED DOMAIN CHECK` for new research.

After a study finishes, identify `HANDOFFS TO OTHER SPECIALISTS` whenever findings can materially help another domain.

The objective is active shared learning, not absolute non-duplication.

## Overlap rule

Duplicate or overlapping research is allowed when it has a stated analytical purpose.

Valid reasons include:

- replication / calculation check;
- independent validation;
- second check / adversarial review;
- contradiction investigation;
- method / standard / dataset comparison;
- cross-domain or project transfer validation;
- prerequisite learning;
- second-specialist interpretation;
- project urgency or risk reduction;
- real browser/device validation of abstract design research.

Avoid only repetition that adds no analytical value.

## Key collaboration boundaries

### Interaction ↔ Content

Interaction owns the actual state/action/recovery contract. Content owns how that contract is named and explained. Content must not simplify away real distinctions such as pending, failure and ambiguous outcome.

### Type ↔ Content

Content defines semantic strings/terminology; Type owns glyph/font/metric/rendering systems. Necessary wording may create geometry/wrapping stress that should be validated rather than shortened solely for visual fit.

### Color ↔ Content

Color visually encodes semantic states; Content verbalizes them. Meaning must remain understandable when color is unavailable or transformed.

### Web ↔ Content

Web integrates Content in real forms, navigation, components, responsive layouts, browser accessibility and runtime states, then returns transfer failures when implementation changes meaning or discoverability.

## Curriculum progression

The studio uses five stages:

1. Foundation
2. Intermediate Professional Practice
3. Advanced / Systems Practice
4. Production & Authorship
5. Research & Advisory

No stage or specialist is complete from reading alone.

New specialists inherit this progression and may define domain-specific evidence/gates without weakening the shared standard.

## Completion rule

No global mastery announcement until required curriculum gates are supported by evidence and each specialist can explain, critique, apply, defend, revise, independently assess peer evidence, identify uncertainty, collaborate across domains, and advise across realistic project constraints.

The final measure is project usefulness and design quality, not research volume.
