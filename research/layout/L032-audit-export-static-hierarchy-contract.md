# L032 — Audit Export Static Hierarchy Contract

Evidence purpose: **STAGE 3 SYSTEMS PRACTICE + TRANSFER VALIDATION**.

## RELATED DOMAIN CHECK
I028 supplies export provenance; C041 supplies visual-state survival; W040 supplies runtime reconstruction; CD046 supplies durable event semantics; Type metrics remain provisional.

## Spatial contract
A static export loses interaction, sticky regions, progressive disclosure and focus. It therefore requires an explicit static hierarchy:
1. subject + snapshot/provenance context;
2. current authoritative consequence or explicit authority limitation;
3. safe next/recheck path when meaningful;
4. chronological event history;
5. event detail/provenance.

Historical success must not occupy stronger spatial hierarchy than a current conflict/intervention state merely because it was selected in the interactive UI.

## Stress conditions
Validate narrow printable width, page breaks, long localized strings, long IDs, 200% browser zoom before print where relevant, grayscale, header/footer repetition and event rows split across pages. Keep an event's identity, timestamp semantics, state and consequence together or provide explicit continuation structure.

## Failure conditions
- page break separates an event label from its certainty/consequence;
- sticky/current panel disappears from export leaving only history;
- interactive selection styling becomes static hierarchy;
- long localization pushes provenance off-page or below an unrelated event;
- repeated page headers imply stale historical state is current.

## Evidence boundary
This is a spatial transfer contract, not executed PDF/print geometry or human scanning evidence.
