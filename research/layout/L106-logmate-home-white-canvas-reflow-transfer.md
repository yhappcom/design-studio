## RELATED DOMAIN CHECK

## Project geometry
The draft uses one continuous surface, spacing/baseline hierarchy, restrained hairlines, an open Recent Flights ledger and no repeated-card grammar. This is a valid static direction but not yet responsive evidence.

## Protected relationships
Across 390-class baseline, narrower width, enlarged text and text-spacing stress, preserve:
- header identity ↔ Settings;
- Add Flight / View Logbook as semantically equal direct actions unless product authority changes;
- search label/input ownership;
- Current Period context ↔ paired values;
- each Recent Flight identity ↔ date/route/duration;
- Activity range selector ↔ its projected stats;
- Totals label ↔ value;
- focus/recovery element visibility.

Absolute x/y coordinates, one-line rows and exact section heights are not invariants.

## Reflow order
1. allow intrinsic growth;
2. redistribute local columns;
3. allow row height/wrap where semantics survive;
4. move secondary metadata to a local second line/detail disclosure;
5. use local horizontal scrolling only where simultaneous comparison is genuinely required;
6. use recoverable truncation last.

Do not introduce cards merely to rescue narrow geometry; do not shrink text/targets to preserve the 390px screenshot.

## CRITIQUE / falsifiers
FAIL if reflow changes reading/action order, separates a value from its owning label/record, hides focus behind sticky UI, makes Recent Flights ambiguous, or depends on unfinished custom Type metrics.

## Reproducible validation
Capture semantic rectangles and reading/focus order at baseline, narrow, enlarged and WCAG text-spacing override using the same fixture. Diff protected relationships rather than screenshot pixels. Repeat with actual fallback font.

## HANDOFFS
Type: report wrap/width failures without requesting premature kerning. Interaction: report any reflow that changes action authority. Web: execute as part of production provenance. Content: do not shorten strings until recomposition options are exhausted.
