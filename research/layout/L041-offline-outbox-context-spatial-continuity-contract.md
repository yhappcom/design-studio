# L041 — Offline Outbox Context Spatial Continuity Contract

Evidence purpose: **PRACTICE / TRANSFER VALIDATION**. Spatial companion to I037 and W050.

## RELATED DOMAIN CHECK
- **Type:** queue/context strings use mature fallback; provisional custom metrics do not drive geometry.
- **Color:** C050 supplies cue-degradation conditions.
- **Interaction:** I037 owns dispatch eligibility and outcome truth.
- **Web:** W050 supplies browser/runtime queue evidence.
- **Content:** CD056 supplies complete origin/current-context wording.
- **UX:** human scan/discoverability evidence remains OPEN.

## Information spine
For a queued consequential operation preserve, in this order of meaning rather than rigid pixels:
`operation/object → origin context → current context → dispatch certainty → safe action/recheck → outcome/history`.

Origin context must remain locally associated with the queued operation. Current context belongs to global/current navigation. The two may not collapse into one unlabeled context badge.

## Responsive/adaptive behavior
At narrow width, 200% text, pseudo-expansion and long tenant names:
- wrap origin/current labels before truncating authority meaning;
- move secondary metadata below the operation before separating origin context from the action;
- keep recheck/suspended explanation reachable before destructive queue removal;
- preserve DOM/reading order matching the information spine;
- when a focused dispatch control is removed after context mismatch, move focus to the nearest persistent queue item/status region, not to an unrelated global control.

## Queue density
Dense outbox views may summarize repeated origin context only when each item retains programmatic association and expanding/filtering cannot make B appear to own A operations. Sorting by time/status must not change authority interpretation.

## Static transfer
Print/export/history must retain operation-origin context and snapshot/current-context provenance. Interactive selection/focus styling is omitted or clearly non-authoritative.

## Failure conditions
FAIL if responsive collapse, virtualization, sticky headers, context chips or truncation visually attach an A operation to B; if safe recheck becomes unreachable; or if removal of a disabled action destroys focus continuity.

## Evidence boundary
No browser geometry, AT, physical-device, human scanning or production outbox PASS is claimed until W050 or product runtime artifacts exist.

## HANDOFFS TO OTHER SPECIALISTS
W050 captures DOM order, bounding geometry, focus before/after and responsive screenshots. CD056 must provide non-fragmented labels. C050 checks cue independence.
