# L038 Retention Expiry / Recovery Spatial Continuity Contract

Evidence mode: SYSTEMS PRACTICE / TRANSFER VALIDATION.

## Purpose
Preserve comprehension when recoverability changes around a retention boundary without allowing countdown geometry or disappearance to become the authority signal.

## RELATED DOMAIN CHECK
I034 owns recoverability/action truth. C047 owns visual precedence. W047 supplies actual responsive/browser geometry. CD053 owns semantic labels. T021 metrics remain provisional.

## Information spine
Keep, in this order of meaning rather than fixed pixels: object identity → current existence/recoverability consequence → certainty/evidence → retention boundary information → safe action or recheck → durable history.

At narrow widths, zoom, 200% text, localization and print/export, do not separate a Restore/recheck action from the evidence that explains whether it is currently safe. A historical Delete success must not visually dominate current recovery-unavailable or authority-unavailable state.

## Boundary behavior
When a local countdown reaches zero, reserve enough stable space for the state to become recheck-required/authority-unavailable without destructive layout collapse. Do not remove the row and its history merely because recovery becomes unavailable. If a recovered/recreated object returns to a live list, preserve a route to the prior deletion/retention history.

## Validation matrix
320px/narrow mobile, tablet/desktop, 200% text, long pseudo-localized labels, RTL-ready ordering review, keyboard focus, forced colors, print/static export, offline return after boundary.

## Evidence boundary
No executed geometry, AT, physical-device, print or human scanning/workload PASS is claimed.
