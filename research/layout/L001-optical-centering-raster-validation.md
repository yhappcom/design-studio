## Objective

Strengthen the L001 optical-centering protocol without pretending that a browser screenshot can measure human perception.

The experiment asks a narrower question:

> If a fixed hit target contains asymmetric visual shapes, how far does the rendered darkness/ink centroid sit from the target center, and does one universal integer offset survive across shapes and sizes?

The answer is used only as a **measurable pre-critique diagnostic**. It is not promoted to a perceptual law.

## Method

### Fixed interaction geometry

Each specimen uses a `48×48 CSS px` target.

The target never moves or shrinks.

Only the visual child may be translated.

This preserves the Interaction/Accessibility contract while testing a visual correction separately.

### Visual sizes

The same vector shape is rendered at:

- 16px;
- 24px;
- 32px;
- 40px.

### Device-pixel ratios

- DPR 1;
- DPR 2.

### Shapes

Six intentionally different asymmetric or directionally weighted forms:

- play triangle;
- right chevron;
- send/paper-plane-like mark;
- irregular stepped mark;
- base object + upper-right badge;
- bookmark with lower notch.

### Measured quantity

For each screenshot, darkness weight is:

`weight = 255 - grayscale_pixel`

The darkness-weighted raster centroid is calculated and compared with the fixed target center.

Then an integer candidate correction is generated by rounding the negative centroid error and the result is re-rendered.

## Critical limitation

The resulting centroid is a **raster mass proxy**.

It is not:

- perceived optical center;
- aesthetic preference;
- icon recognizability;
- human balance judgment.

# Results

## Play triangle

DPR1 zero-placement horizontal error:

- 16px visual: about `−0.66px`;
- 24px: `−0.99px`;
- 32px: `−1.35px`;
- 40px: `−1.66px`.

Rounded candidate correction:

- `+1px` at 16–32px;
- `+2px` at 40px.

At 24px, `+1px` reduced the measured mass-centroid error to about `0.01px`.

### Consequence

Even for one familiar directional shape, the same integer offset does not survive all visual sizes in this controlled target.

Therefore:

> `play icon = +1px` is not a safe universal token.

---

## Chevron and send marks

Both also placed their raster mass left of the target center when geometrically centered.

At DPR1:

- 24px chevron zero error ≈ `−0.88px`; `+1px` candidate residual ≈ `0.12px`;
- 24px send zero error ≈ `−0.84px`; `+1px` candidate residual ≈ `0.16px`.

These agree directionally with play at that size, but the magnitude differs.

### Consequence

Similar directional semantics do not imply identical mass distribution.

Do not build one family-wide correction solely from icon meaning such as “forward/right.”

---

## Irregular mark and badge object

The irregular stepped mark produced much smaller horizontal error and a modest downward mass shift. Integer correction remained `0,0` across most tested sizes because a 1px move would overshoot the measured centroid.

The badge object shifted raster mass toward the upper-right. At smaller sizes, the measured displacement remained below the integer threshold; at 40px a rounded candidate became left/down.

### Consequence

A visible asymmetry does not automatically justify an integer optical nudge.

A small measured imbalance can be made worse by blindly applying the same correction used for triangles or chevrons.

---

## Bookmark

The bookmark was horizontally centered but increasingly top-heavy in the raster-mass proxy as visual size increased.

DPR1 vertical zero error:

- 16px: about `−0.28px`;
- 24px: `−0.45px`;
- 32px: `−0.63px`;
- 40px: `−0.74px`.

The rounded candidate changes from no correction at 16–24px to `+1px` downward at 32–40px.

### Consequence

Optical correction can be vertical as well as horizontal, and size can change whether an integer correction is justified.

---

## DPR transfer

DPR2 preserved the broad direction and magnitude of the tested raster-mass biases.

This is useful replication but does **not** prove physical-device perceptual equivalence.

Different platform renderers, subpixel behavior, scaling and display characteristics remain open.

# SYNTHESIS

The controlled evidence supports the following narrower rules.

### 1. Start geometric, then measure

A geometric center is still the correct neutral starting condition.

Do not add optical offsets by default.

### 2. Separate hit target from visual child

The 48px target should remain stable while the visual child is corrected.

A visual nudge should not silently move interaction geometry.

### 3. Correction is shape- and size-dependent

The tested play icon alone moved from a `+1px` candidate to `+2px` as visual size increased.

Therefore a universal pixel nudge is not supported.

### 4. Raster mass is evidence, not the verdict

A centroid can identify why geometric centering may be suspicious, but only human comparison can establish whether a candidate is actually perceived as better centered.

### 5. Integer-pixel correction is not always appropriate

Several specimens had measurable offsets smaller than 0.5px. Rounding them to a whole pixel would overshoot.

Production systems may need:

- no correction;
- subpixel transform;
- source-asset redesign;
- size-specific asset/optical variant.

Which one is appropriate depends on the rendering stack and component.

---

# STUDIO JUDGMENT — Revised optical-centering protocol

For project work:

1. define the interaction/hit bounds;
2. define the visual child's geometric reference;
3. measure vector/raster mass only as a diagnostic;
4. inspect at intended rendered size and target DPR;
5. generate `0`, `+δ`, `−δ` candidates rather than editing one direction indefinitely;
6. keep hit target fixed;
7. compare candidate order blindly when practical;
8. include adjacent text/other icons if the component is not standalone;
9. repeat at materially different visual sizes;
10. record any correction as component/size-specific, not a global law;
11. fix the source asset instead if repeated offsets are compensating for defective geometry;
12. require human evidence before claiming perceptual/optical superiority.
