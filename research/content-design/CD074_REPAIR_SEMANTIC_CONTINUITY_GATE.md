# CD074 — Repair Semantic Continuity Gate

Status: PRACTICE / TRANSFER VALIDATION
Date: 2026-09-18

## Purpose
Prevent layout/interaction repair from buying space by weakening financial meaning, state truth, localization, or recovery wording.

## Protected distinctions
- distribution ≠ profit
- partial/unavailable ≠ zero
- estimated ≠ final
- gross ≠ net
- refund/additional tax signs remain explicit
- ambiguous outcome ≠ known success or known failure

## Surface chain
For each protected message trace source key/API → locale selection/fallback → visible UI → accessible name/description → validation/recovery → history/export where applicable.

## Change classification
A repair-time string change must be classified as: REFLOW_ONLY, MEANING_EQUIVALENT_ABBREVIATION, TERMINOLOGY_SUBSTITUTION, SEMANTIC_DELETION, or STATE/CONSEQUENCE_CHANGE. The last two require rejection or explicit product/content review rather than silent layout acceptance.

## Localization stress
Exercise long localized strings, plural/number/currency formatting, signed values, date formatting, and fallback behavior through the product's actual localization pipeline. Synthetic English fixtures are not localization closure.

## Evidence boundary
Automated string/state continuity does not establish comprehension or tone appropriateness with real users. Human evidence remains OPEN.

## Handoff
Type owns rendering classification; Layout owns reflow; Color owns redundant semantic state; Interaction owns recovery behavior; Web owns runtime provenance.
