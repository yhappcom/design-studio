# C103 — LogMate brand salience vs semantic-state contradiction audit

Status: **STAGE 3 PRACTICE / CONTRADICTION REVIEW — NOT PASS**

## Purpose
Contribute Color-owned evidence to the mandatory LogMate synthesis gate. The question is not which palette looks premium; it is where brand color may safely operate without corrupting semantic-state hierarchy.

## Source-grounded accessibility constraint
WCAG 2.2 SC 1.4.11 requires at least 3:1 contrast for visual information needed to identify applicable UI components/states against adjacent colors. Color-only communication remains insufficient where another criterion requires non-color differentiation. Forced-colors and user overrides remain separate runtime evidence.

## Semantic salience budget
Color should allocate salience in this order:
1. focus and actionable state when required for operation;
2. invalid/destructive/ambiguous/recovery states according to actual consequence;
3. selection/current context;
4. ordinary hierarchy and grouping;
5. brand recognition/accent;
6. decoration.

This is a STUDIO JUDGMENT derived from existing C091–C102 state-separation evidence and I090 precedence. It is not a universal palette formula.

## Contradiction matrix
- **Brand accent vs focus/state — Class A if same treatment is reused:** a signature accent cannot simultaneously mean brand, focus, selection and success. Resolve with role-separated tokens and redundant shape/text/geometry cues.
- **Premium restraint vs state visibility — Class D:** reduce persistent decorative chroma before reducing consequence-bearing state salience.
- **Light/night continuity vs identical color values — Class B:** identity may preserve relational roles while actual values adapt to background/viewing context.
- **Brand code vs forced colors — Class C:** authored color identity may disappear under forced colors; semantic identity must survive via system colors, structure, labels and state mechanics.
- **Logo exemption vs product UI — scope warning:** logo/brand-name contrast exceptions do not authorize low-contrast functional UI.

## Candidate identity direction
A durable LogMate color code is more plausibly a **relational rule**—restrained neutral operational field plus narrowly scoped accent—than a fixed hue applied everywhere. This is PROJECT-SPECIFIC CANDIDATE only; no palette is selected.

## Reproducible future validation
For every promoted color rule, render the same semantic fixture in light, night/dark and forced-colors, then independent engine/device where possible. Record declared tokens, computed/used values where available, state identity, focus identity, adjacent contrast pairs, non-color redundant cue, stale-state cleanup and 200% geometry interaction. Use the same fixture IDs as Layout/Web.
