# C108 — Cross-surface signature salience transfer

Date: 2026-09-20
Status: Stage 3 PRACTICE / TRANSFER VALIDATION DESIGN

## Question
Can SC-C Quiet Functional Boundary and the LogMate salience hierarchy transfer across surfaces without turning brand accent into semantic authority?

## Transfer contract
Across Home, ledger, Activity, Add Flight, import/review, warning/recovery:
- brand/decorative accent remains subordinate to semantic state;
- focus, selection, invalid, ambiguity, warning, recovery, committed, Saved/Synced remain distinct state axes;
- low chrome means removing decorative competition first, not reducing functional salience;
- light/night consistency means preserving relational hierarchy, not identical RGB values;
- forced-colors is an independent rendering mode, not a palette variant.

## Contradiction review
A repeated accent is not sufficient evidence of identity transfer. It can create false consistency while merging unrelated states. Conversely, a surface may use less brand chroma yet still preserve signature if boundary discipline and semantic salience are intact.

FAIL if:
1. accent color is required to understand state or action;
2. focus/selection/invalidity become indistinguishable in any surface;
3. import ambiguity is rendered as generic error merely for palette consistency;
4. recovery or destructive consequence is quieter than decorative identity;
5. forced-colors removes the only state distinction;
6. stale success/selection paint survives state transition or route return.

## Reproducible validation
For the shared cross-surface fixture capture semantic state IDs plus computed/rendered boundary, text/icon contrast where applicable, focus indicator, selection, validation, recovery, and stale-state cleanup in light/night/forced-colors. Compare hierarchy, not pixel identity.

## Gate consequence
No Stage 3 promotion. Independent-engine and rendered forced-colors evidence on implemented LogMate surfaces remain required.
