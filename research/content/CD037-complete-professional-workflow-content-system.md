## Purpose
Stage 2 covered forms, lifecycle states, onboarding, retrieval, tone and localization. Stage 3 must prove these are one governed content system across a professional workflow rather than separate pattern libraries.

## System model
`domain concept → stable semantic ID → state/action/consequence contract → source string → typed variables → locale realization → surface realization → runtime evidence → revision history`.

## Complete workflow inventory
For the I018 workflow, maintain semantic contracts for:
- find/search/filter/list result;
- record identity and metadata;
- form questions, units, helper text and validation;
- review/confirmation before consequential action;
- pending/progress;
- outcome unknown + reconciliation action;
- confirmed success + durable destination;
- known rejection/failure + supported recovery;
- conflict/review-required;
- empty/no-result/no-record distinctions;
- later retrieval/history/audit trail;
- onboarding/progressive disclosure only where it changes task understanding;
- notification/cross-surface wording where the same event leaves the primary surface.

## Governance rules
1. State chooses message; English text never chooses state.
2. Semantic IDs remain distinct when product truths differ even if English wording converges.
3. Retry wording requires I017/I018 action permission; helper text cannot legalize an unsafe primary action.
4. Professional identifiers are typed separately from ordinary localized numbers/dates.
5. Tone may modulate urgency but may not strengthen certainty.
6. Localization expansion is a layout/runtime test input, not a reason to delete necessary consequence/recovery language.
7. Retrieval terminology must match the terminology used when the record was created/changed unless a migration is explicitly governed.
8. Cross-channel consistency means same truth and consequence, not identical sentence length.

## Critique cases
- “Retry” appears for outcome-unknown because it is shorter: FAIL truth/action contract.
- Search uses “Flight” while edit/history use an unexplained “Sector” for the same object: FAIL terminology continuity unless domain distinction is real and explained.
- Error text names a field but not the corrective action when one is available: incomplete recovery.
- Success toast disappears with no durable history/detail state: Content + Interaction continuity failure.
- Localized string overflows and is truncated: Web/Layout implementation failure; do not shorten source truth by default.

## UX integration
This system reduces semantic inconsistency in expert review and creates measurable implementation checks. It does not establish user comprehension, trust, learning, workload or task success. Those remain HUMAN EVIDENCE OPEN.
