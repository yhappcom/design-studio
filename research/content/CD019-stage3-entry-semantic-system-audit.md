## First semantic source-of-truth model
Every consequential user-facing message should be derivable from structured truth rather than authored as an isolated string:

`domain object + lifecycle state + user action availability + consequence + recovery certainty + persistence/sync scope + channel/surface + locale/context`

Example state families to preserve across phone/tablet/web and later notification/email:
- saved locally;
- pending remote/sync confirmation;
- confirmed;
- known failure with safe retry;
- outcome unknown with verification path;
- offline/stale;
- conflict requiring user resolution.

The model deliberately prevents tone or brevity from merging materially different states.

## String/content architecture requirements
- stable terminology IDs separate concept identity from displayed wording;
- literal operational identifiers are non-translatable data, not prose;
- interpolation/plural/date/number rules belong to message schema, not manual concatenation;
- helper/error/recovery variants share semantic source fields;
- channel variants may change ordering/detail but not underlying truth;
- translator context must identify object, state, consequence and UI location;
- long expansion is a layout/Web stress input, not a reason for semantic deletion.

## Governance contract
A concept/state change must trigger review of: terminology entry → action labels → form/helper strings → state/recovery messages → search/filter/settings labels → notification/email variants → localization context → accessibility names/status exposure. This is change propagation, not a copy deck.

## Predeclared failure conditions
- same concept receives multiple names without intentional scope;
- display string becomes the canonical identifier;
- pending/outcome-unknown becomes failure for brevity;
- concatenated fragments assume English word order;
- color/location/direction words are required to understand an action;
- notification claims stronger certainty than in-product state;
- localization expansion is solved by deleting consequence/recovery information;
- governance has no owner/change path.
