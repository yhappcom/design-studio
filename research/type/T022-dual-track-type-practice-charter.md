# T022 — Dual-track Type practice charter after T021

Classification: **METHOD CORRECTION + CURRICULUM PRACTICE + PRODUCT TRANSFER**

## Purpose
T021 closed one current LogMate whole-family bespoke route; it did **not** establish that new typeface design is impossible or that the Type specialist should become only a font-selection specialist.

T022 therefore separates two simultaneous obligations:

1. **Product typography track** — improve LogMate now using the mature bundled `LogMateRoboto` / `LogMateNotoSansKR` baseline without delaying the product for speculative font authorship.
2. **Type-design mastery track** — continue learning how to draw, space, engineer and validate original typefaces, using T021's drawing failure as method evidence rather than as a prohibition on future authorship.

Neither track may impersonate the other. A research typeface is not a product recommendation until it earns transfer evidence; a mature product font is not proof that the studio has mastered type design.

## RELATED DOMAIN CHECK
- **Layout/Interaction:** numeric alignment and density are joint font-feature/column-geometry problems; layout must remain flexible while Type tests role behavior.
- **Web:** custom-family transfer remains blocked until a future candidate earns drawing/product value; mature product typography can be tested now.
- **Content:** airport codes, flight numbers, registrations, time/duration and totals remain literal proof strings and must not be rewritten to flatter a typeface.
- **Color:** color cannot repair character ambiguity.
- **UX:** human recognition/scan performance is deferred to real app validation and must not be simulated.

## Track A — product typography
### A1. Role inventory
Test at minimum:
- airport identifiers: `ICN NRT JFK LAX`;
- flight identifiers: `KE123`, `B737-900`, `HL8240`;
- duration/time: `01:35`, `12:05`, `1284:35`;
- counts/totals: `1,284`, `8,888`, `111.1`;
- ambiguity controls: `0O`, `1Il`, `5S`, `8B`;
- Korean/Latin seams using the actual bundled Korean companion.

### A2. Alternatives
Compare materially different role systems rather than one styling direction:
- **P — proportional baseline:** current proportional figures/text everywhere;
- **T — selective tabular figures:** proportional prose/identifiers, tabular figures only where column comparison materially benefits;
- **G — geometry-led alignment:** keep font defaults and solve alignment through column/tabular layout formatting where possible;
- **B — bounded feature hypothesis:** use only a narrowly justified feature/alternate if the actual font/runtime supports it; no global monospace substitution.

### A3. Product acceptance
A role system advances only if it improves a defined task without creating worse width, fallback, localization, hierarchy or implementation behavior. Exact Flutter/native feature support must be verified before a product recommendation.

## Track B — original type-design mastery
### B1. T021 diagnosis
T021 proved that parameter operationality, full bounded coverage and deterministic raster do not create professional drawing quality. The next authorship curriculum must therefore put **optical drawing discipline before architecture automation**.

### B2. Drawing sequence
Practice should proceed from a small control set before broad repertoire:
1. `H O` — vertical/round proportion, overshoot, straight-to-curve contrast;
2. `n o` — lowercase rhythm, shoulder tension, counter proportion;
3. `S 5` — related silhouette but different construction grammar;
4. `B 8` — bowl/counter system;
5. `I l 1` and `O 0` — ambiguity families without decorative gimmicks;
6. diagonals `A V X` — joins, compensation and texture.

For each set use the order:
`drawing hypothesis → enlarged outline critique → black/white countershape critique → target-size raster → drawing revision → only then sidebearing rhythm`.

Kerning remains forbidden as a repair for immature drawing or base spacing.

### B3. What must be learned explicitly
The mastery track must accumulate evidence in:
- skeleton and proportion;
- curve tension and extrema;
- overshoot as optical compensation;
- stroke modulation/contrast logic;
- joins and terminals as a coherent grammar;
- countershape and internal whitespace;
- figure design as a system;
- sidebearing rhythm and word texture;
- spacing before kerning;
- interpolation/weight only after master drawings are coherent;
- rasterization/hinting/rendering transfer;
- multiscript/fallback relationships;
- source/build/QA/release engineering.

### B4. Method change from T021
Do not begin the next original family as a large parameter dictionary that generates broad repertoire first. Automation may measure/build/reproduce, but the first gate is visually coherent control glyphs whose outline decisions are explicit and critiqueable.

A future custom LogMate hypothesis may reopen only after the mastery track can produce a bounded control family that survives drawing critique and demonstrates a concrete product role unavailable or materially weaker in the mature baseline.

## Shared evidence ladder
`source/history → drawing or role hypothesis → practice artifact → critique → deterministic measurement → rendering transfer → product comparison → native/browser/device transfer → human validation`

Human evidence cannot be inferred from raster quality, contrast arithmetic, source authority or model critique.

## Stage decision
**T022 OPEN.** Product role-system work and original type-design mastery now run in parallel. T021's rejected bespoke product route remains closed; original typeface learning remains active.

## Next executable block
1. build the exact LogMate product-role corpus and inspect actual bundled font feature tables/metrics where available;
2. compare P/T/G alternatives without assuming tabular support;
3. create the first mastery control-glyph exercise around `H/O/n/o` with explicit optical-drawing criteria;
4. keep product recommendation and authorship-learning verdicts separate.

## HANDOFFS
- Layout: return numeric alignment cases where geometry is preferable to font-feature dependence.
- Content: preserve exact literal corpus and mixed-script examples.
- Web: use mature product typography until a custom candidate earns transfer.
- Color: no color-coded ambiguity workaround.

## Evidence boundary
This charter does not claim a new custom font exists, that Roboto is universally superior, that tabular figures work in the shipped Flutter stack, or that any option improves human pilot performance.
