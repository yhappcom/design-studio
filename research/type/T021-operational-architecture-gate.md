# T021 — Operational Architecture Gate

Classification: **CONTRADICTION REVIEW + METHOD CONTROL**

## RELATED DOMAIN CHECK
- Layout/Interaction L011 opens Stage 3 multi-surface practice but explicitly must tolerate current proportional control and future metric change.
- Web W019 closes Stage 2 without requiring transfer of a drawing-invalid custom font.
- Content CD019 preserves literal identifiers and consequential strings as proof material.
- Color C019 keeps character identity independent of hue.

## Problem
The construction-complete A/B reset closed predecessor delegation, but the latest source audit found architecture tokens (`corner`, `join`, `diag_comp`, `terminal`) that were metadata-only or insufficiently consumed. Therefore `different parameter dictionaries + complete cmap + different widths` is not enough to prove two implemented architectures.

## Gate model
Before another raster comparison, every declared architecture distinction must have:
1. a named semantic purpose;
2. an explicit glyph-class consumer map;
3. an outline-affecting implementation path;
4. an assertion that the consumer exists;
5. at least one deterministic geometry delta when A and B differ;
6. no predecessor delegation for the bounded operational repertoire.

## Required operational tokens
- stem thickness → straight stems and crossbars;
- round-stem compensation → O/o/0 and bowls;
- aperture → C/G/S/5 family where applicable;
- overshoot → round cap/lowercase groups;
- diagonal compensation → A/V/X/K/R leg and relevant figures;
- terminal policy → open forms and straight endings;
- bowl/join policy → B/D/P/R/8 construction;
- shoulder tension → n/S and related transitions;
- figure-width mode → all 0–9 metrics, not selected figures;
- zero treatment → 0 only, with O geometry held independently inspectable.

## Assertion contract
A future executable harness must fail before font export when:
- a declared token has zero consumers;
- A/B token values differ but no intended outline/metric delta is observable;
- any operational digit/glyph delegates to predecessor geometry;
- a glyph consumes an unrelated token merely to satisfy coverage;
- kerning is present before drawing and general spacing pass.

## Decision rule after operational rebuild
If genuinely operational A and B both remain drawing-invalid at 14/17/24px under the same corpus, stop bespoke local iteration and run a **METHOD COMPARISON** against current proportional Roboto. The question then becomes whether a bespoke operational family creates enough product value to justify further authorship cost, not which broken custom candidate is less broken.

## KEEP / REWORK / REJECT
KEEP: exact 36/36 corpus, kerning OFF, deterministic target-size proof, A/B alternative framing.
REWORK: architecture implementation so declared distinctions actually reach outlines/metrics.
REJECT: metadata-only architecture claims; spacing or kerning work before drawing validity.

## HANDOFFS TO OTHER SPECIALISTS
- Layout/Web: do not freeze geometry around either A/B candidate.
- Content: keep literal identifiers/numeric strings unchanged for proofing.
- Color: no color compensation for ambiguity.

## Evidence boundary
This is a method gate, not a drawing PASS. Human recognition/readability and product preference remain untested.
