## PURPOSE
Test whether materially different Home presentations preserve the same professional workflow authority without inventing behavior from visual affordances.

- **Color:** C119 preserves semantic rank without requiring palette sameness.

- **Content:** CD123/CD124 require accessible label/action parity and block unsupported status language.

## CONTRADICTION REVIEW
Candidate 05 and 07 may present controls, rows and hierarchy differently, but visual difference must not redefine underlying authority. The reusable chain is:

`visible affordance → enabled action → requested transition → pending/unknown state where applicable → authoritative result → restored/projected state`.

Candidate-independent invariants:
1. Month navigation changes the same period authority and projection, regardless of control styling.
2. Recent Flight activation resolves the same stable record identity; Back/return restores appropriate Home context.
3. Add Flight and View Logbook remain destination/action identities rather than decorative labels.
4. Activity range selection distinguishes proposal/focus from committed selection and resulting projection.
5. Search remains a shell until SEARCH-001 behavior exists; neither concept's visual field authorizes invented search behavior.
6. Visible 44px geometry does not prove actual hit target, focus order or keyboard/touch behavior.
7. Static selected/current styling does not prove committed state.

## PRACTICE / CRITIQUE
Reject concept-specific hidden behavior introduced only because one candidate visually resembles a familiar control. Also reject forcing identical control presentation merely to make the interaction model consistent. Consistency belongs in action/state/recovery truth, not necessarily visual form.

## REPRODUCIBLE VALIDATION
Run the same fixture on both exact builds: month previous/next and restoration; Recent→record→Back; Add Flight→return; View Logbook→return; Activity range change→projection→restore. Record source/build, platform/input, semantic control identity, enabled state, focus before/after, route/state mutation, authoritative result, scroll/return context and any recovery. Repeat each build twice before cross-platform transfer.

## RESULT
The comparison isolates **workflow authority as invariant and control presentation as variable**. No Stage 3 PASS.
