## Purpose
Prior Interaction work proved ambiguity/reconciliation locally. This study expands the oracle to a complete professional-record workflow so local correctness cannot hide cross-step contradictions.

## Workflow model
`find/open record → inspect current truth → initiate consequential operation → pending → transport observation → certainty classification → enabled safe action → reconciliation → authoritative outcome → conflict resolution if required → stable record/history → later retrieval`.

Every transition records: semantic state ID; authoritative source; available actions; destructive/reversible consequence; interruption behavior; persistence expectation; navigation/history behavior; content message ID; focus destination; and recovery route.

## Invariants
1. **No invented certainty:** transport symptoms never promote themselves to authoritative success/failure.
2. **No unsafe action promotion:** outcome-unknown prioritizes reconciliation; retry requires a documented idempotency/deduplication contract.
3. **No dead-end success:** confirmed completion must expose a stable destination or next task, not merely a transient toast.
4. **No hidden conflict:** if local and authoritative records diverge, conflict/review-required is explicit; last-write-wins is not silently presented as certainty.
5. **History coherence:** browser/app back navigation must not replay a consequential operation or erase the user's understanding of outcome.
6. **Interruption continuity:** reload/background/resume must preserve enough operation identity to reconcile safely when the product contract supports it.
7. **Retrieval continuity:** later search/list/detail surfaces must expose the authoritative result consistently with the operation history.

## Non-human adversarial cases
- response lost before commit;
- response lost after commit;
- reload during outcome-unknown;
- duplicate dispatch gesture/click;
- stale list after confirmed detail update;
- conflict discovered during reconciliation;
- navigation back/forward around pending/confirmed states;
- localization expansion causing the safe action to wrap/reflow;
- sticky/keyboard-reduced viewport obscuring the safe action.

## Cognitive-load discipline
The system should expose the minimum information needed to decide the next safe action, but cognitive-load claims remain hypotheses until human evidence. Static complexity counts, expert critique or model judgment cannot establish workload reduction.

## Accessibility boundary
WCAG 2.2 remains the current baseline. Keyboard/focus/status/reflow checks can be executed non-human where technically valid; AT comprehension and task success require appropriate evidence.

## Closure package for this oracle
A product-transfer package should contain one stable workflow fixture, deterministic operation IDs, route/history captures, authoritative backend records, rendered semantic IDs, responsive/focus geometry, locale cases, and explicit human-study backlog. Missing production backend contracts must be labeled DEPENDENCY rather than inferred.
