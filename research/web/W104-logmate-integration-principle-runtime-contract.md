# W104 — LogMate Integration-Principle Runtime Contract

Status: **PROJECT-SPECIFIC SYNTHESIS / STAGE 3 NOT PASSED**

## PURPOSE
Define what an Integration Principle must survive before Web can treat it as product-transfer evidence. This extends W103; it does not add another isolated Chromium micro-test.

## RELATED DOMAIN CHECK
T073, C104, I091, L095, CD109 and the final project contradiction register checked. H4 cross-surface transfer and H5 runtime evidence are controlling.

## SYNTHESIS
### IP-W1 — A design principle is executable only when its invariants are observable
Each principle needs named semantic/geometry/state invariants that can be inspected in the product, not only prose or screenshots.

### IP-W2 — Promotion is cross-surface and runtime-based
Required ladder: explicit rule → implemented LogMate surface → production Web build → served primary engine → independent engine → enlarged text/text spacing → light/night/forced colors where applicable → real route/network/font state → physical device where relevant.

### IP-W3 — Fallback and failure states are part of the design
Font fallback/load failure, offline/network ambiguity, stale/restored state and route lifecycle must preserve meaning and workable geometry. Happy-path identity alone is insufficient.

### IP-W4 — Browser evidence and human evidence remain separate
Rendered/runtime success can establish implementation behavior. It cannot establish pilot preference, trust, comprehension, workload or discoverability.

### IP-W5 — Performance evidence keeps provenance
Lighthouse/DevTools/CI remain LAB/synthetic. LCP/INP/CLS become FIELD evidence only with provenance-bearing representative RUM/aggregate data.
