# W119 — Candidate 05/07 Cross-Concept Production Comparison

Date: 2026-09-20
State: **CONTRADICTION REVIEW / PRODUCTION TRANSFER PLAN — STAGE 3 PRACTICE, NOT PASS**

## PURPOSE
Convert the Candidate 05/07 contradiction review into one production comparison protocol. The goal is not to make the concepts visually converge; it is to determine which cross-domain invariants survive materially different implementations.

## RELATED DOMAIN CHECK
- **Type:** T088 — role/representation/scaling/fallback/fit invariants; exact metrics remain concept variables.
- **Color:** C119 — semantic rank and redundant state boundaries are invariant; palette atmosphere is variable.
- **Layout/Interaction:** I106/L110 — workflow authority and protected relationships are invariant; control/composition presentation may differ.
- **Web:** W117/W118 provide candidate-specific promotion ladders; neither has runtime closure.
- **Content:** CD125 — terminology and semantic/a11y parity are invariant; visual prominence may differ.

## CROSS-CONCEPT PROVENANCE PACKET
For each exact candidate build capture the same schema:
- source commit, Flutter/toolchain/build identity, data fixture and service/runtime version where applicable;
- platform, OS, engine/browser/display mode, viewport/window, SafeArea and input modality;
- text scaling/accessibility settings, requested/resolved font where observable and fallback condition;
- route/history state, focus before/after, semantic control identity and visible+a11y payload;
- bounding boxes/target geometry, clipping/wrapping/scroll behavior and semantic reading order;
- Interaction request/result/projection authority for month, Recent, Add Flight, View Logbook and Activity fixtures;
- semantic color/state IDs plus non-color state boundaries;
- screenshots/render captures as supporting evidence, never as sole runtime proof.

## EXECUTION ORDER
1. Exact-source analyze/relevant widget-golden-accessibility tests for each candidate.
2. Primary native runtime baseline; repeat same build twice (**REPLICATION**).
3. Narrow/SafeArea/max supported text scaling/mature fallback/accessibility-mode stress.
4. Compare invariant failures without normalizing visual composition (**CONTRADICTION REVIEW**).
5. Second native platform where product scope applies (**TRANSFER VALIDATION**).
6. Served Flutter Web and independent browser where product scope applies; inspect semantics/focus/route behavior.
7. Physical device/PWA, screen reader and representative-human work remain later evidence classes, not inferred from automation.

## ACCEPTANCE LOGIC
A candidate difference is not a failure merely because typography, containment, density, palette or control shape differs. A failure occurs when a shared invariant breaks: semantic terminology/authority changes without product reason; state rank collapses; protected ownership/order is lost; text is distorted/shortened to preserve screenshot geometry; accessible payload diverges from visible/action truth; or runtime provenance cannot establish the claimed result.

## WCAG 2.2 / PERFORMANCE BOUNDARY
WCAG 2.2 remains the current W3C accessibility baseline for web evaluation. Automated Flutter/browser checks are evidence inputs, not a WCAG conformance claim. Lighthouse, DevTools, CI and synthetic traces remain **LAB**. LCP/INP/CLS become **FIELD** evidence only from provenance-bearing representative RUM/aggregate; no field evidence is claimed here.

## RESULT
The studio now has one falsifiable cross-concept production comparison instead of two isolated promotion packets. This reduces duplicated validation while preserving Candidate 05/07 visual independence. No Web Stage 3 PASS.
