# W103 — LogMate synthesis runtime transfer and evidence-promotion gate

Status: **STAGE 3 PRACTICE / PRODUCT-TRANSFER GATE — NOT PASS**

## Purpose
Define Web-owned runtime evidence needed before abstract LogMate synthesis principles become web/PWA design rules. This avoids accumulating another isolated Chromium micro-test.

## RELATED DOMAIN CHECK
- **Type:** T072 keeps mature fallback as control until T021 closes.
- **Color:** C103 requires light/night/forced-colors role separation.
- **Layout/Interaction:** I090/L094 define state precedence and cross-surface geometry transfer.
- **Content:** CD109 requires complete semantic/localization stress, not fit-driven shortening.
- **Project gate:** visual rules cannot be promoted from Home/static evidence alone.

Analytical purpose: **TRANSFER VALIDATION + EVIDENCE PROMOTION AUDIT**.

## Promotion ladder
A synthesis candidate is not web-production evidence until it progresses through:
1. explicit semantic/design rule and failure condition;
2. implemented LogMate component/surface;
3. production Web build;
4. served primary engine with provenance;
5. independent engine;
6. 200%/reflow and text-spacing stress where applicable;
7. light/night/forced-colors as relevant;
8. real route/history/network/font-loading state where the rule depends on them;
9. physical mobile/iPad evidence when device behavior matters.

Passing one rung does not imply the next.

## Cross-surface runtime matrix
At minimum exercise Home, View Logbook, Activity Detail, Add Flight and Customize/import review. Use shared fixture IDs and capture build/commit, route, browser/version, viewport/DPR, locale, theme/forced-colors, font loaded/fallback identity, semantic state, focus, relevant rectangles, overflow/scroll ownership and screenshot/trace hashes where available.

## Contradiction matrix
- **Static visual coherence vs runtime reflow — Class C:** static approval cannot override clipping/wrap/focus failures.
- **Brand type vs font-load failure — Class C:** fallback must preserve meaning and workable geometry.
- **Brand color vs forced colors — Class C:** semantic operation must survive authored-color loss.
- **Home identity vs dense ledger fitness — Class B:** a Home-only rule is surface-specific until transferred.
- **Smooth motion vs reduced motion/performance — Class D:** identity motion must degrade without losing state continuity.

## WCAG 2.2 baseline
Use current WCAG 2.2 as the accessibility reference. Reflow, text spacing, non-text contrast, focus, target/dragging requirements are evaluated by their actual applicability; this file does not claim full conformance from a subset of checks.

## Performance evidence boundary
Lighthouse, DevTools and CI synthetic measurements remain **LAB**. LCP/INP/CLS become **FIELD** evidence only when provenance-bearing representative RUM/aggregate data exists. A visual-system decision must not claim field performance benefit from lab surrogate alone.

## Reproducible validation bundle
For each candidate design code, execute the same fixture twice per runtime family. Diff semantic state, focus identity, font identity, key geometry, overflow, theme/forced-color survival and recovery result. Record discrepancies rather than averaging them away. If an independent engine contradicts primary-engine behavior, classify and reproduce before promotion.

## CRITIQUE
The repository now has substantial abstract and Chromium evidence. The highest-value Web work is closure through actual LogMate routes/builds and independent engines, not additional isolated demonstrations. The new synthesis gate makes this a prerequisite for durable design-code promotion.
