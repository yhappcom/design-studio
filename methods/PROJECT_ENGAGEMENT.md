# Project Engagement Method

Design Studio should join new product work as a professional design partner, not as a final styling pass.

## Phase 1 — Understand

- product purpose and boundaries
- primary users and contexts
- critical tasks
- information/data model
- platform and environment constraints
- known implementation state
- accessibility and localization requirements

Deliverable: concise design brief with unknowns separated from facts.

## Phase 2 — Research

- direct competitors only when useful
- adjacent product categories
- editorial/industrial/graphic precedents
- domain-specific artifacts
- platform conventions
- typography and content constraints

Deliverable: precedent map that extracts principles rather than visual parts to copy.

## Phase 3 — Frame

For every core surface define:

1. the question the screen answers;
2. the primary object/value;
3. the primary action;
4. supporting information;
5. secondary navigation;
6. what can be removed or deferred.

Deliverable: information hierarchy before styling.

## Phase 4 — Compose

Produce multiple materially different compositions. Do not vary only color/radius.

At least one proposal should be design-led and free from current implementation bias. A contract-aligned control may be kept for comparison when helpful.

Deliverable: compositions with explicit rationale.

## Phase 5 — Critique

Evaluate:

- clarity
- task fit
- hierarchy
- visual authorship
- genericness
- information density
- typography
- interaction legibility
- accessibility path
- cross-surface coherence
- implementation risk

Label major decisions KEEP / REWORK / REJECT.

## Phase 6 — Validate

Test representative stress cases:

- narrow/large viewport
- large text
- keyboard/focus states
- empty/error/loading
- long labels and user data
- grayscale
- low/high glare when relevant
- reduced motion
- both physical orientation directions where relevant

## Phase 7 — Reconcile with engineering

Only after the design proposition is coherent:

- identify required product-contract changes
- classify implementation difficulty
- distinguish essential design intent from negotiable technique
- define fallback without pretending it is the preferred design
- document compromises explicitly

## Phase 8 — Production review

Compare implemented output with accepted design intent on real target devices. Treat discrepancies as design/implementation issues to resolve, not silent drift.

## Anti-patterns

- engineering schema becomes the screen hierarchy by default
- component library determines composition
- design review begins with “what is easiest to implement?”
- visual references are copied as motifs
- accessibility is postponed until handoff
- every project inherits the previous project's visual language
